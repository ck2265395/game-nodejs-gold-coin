# 接金币：第六步

已完成背景、地面和篮子，并加入键盘移动。按住左右方向键或 A、D 移动，松开停止；一枚金币会从顶部下落，接住加 1 分，漏接扣 1 条生命，生命耗尽后显示最终得分，可点击重新开始。

## 启动

在项目目录打开终端，安装依赖并启动（需要 Node.js 和 npm）：

```powershell
npm install
npm start
```

打开 http://localhost:3000 。按 Ctrl+C 停止服务。依赖安装后也可以直接执行 `node server.js`。

当前 Codex 环境没有 PATH 中的 npm，首次依赖已使用环境自带的 pnpm 安装；你现在可以直接运行 `node server.js`。在有 npm 的普通 Node.js 开发环境中，使用上面的标准命令即可。

如果 3000 已被占用，在 PowerShell 中设置 `$env:PORT = '3001'`，再启动并访问 http://localhost:3001 。

## 按什么顺序读代码

1. `server.js`：Express 把 public 目录里的文件发送给浏览器。
2. `public/index.html`：创建 480 × 640 的画布，加载 CSS 和 JavaScript。
3. `public/game.js`：浏览器取得 2D 绘图上下文，再执行 drawScene()。
4. `public/style.css`：让画布适应屏幕宽度，高度按比例缩放。

Node.js 执行 server.js；浏览器执行 game.js。修改 game.js 后刷新页面即可看到变化，修改 server.js 后需要重启服务。

## Canvas 的坐标

原点 (0, 0) 在左上角，x 向右增加，y 向下增加。画布内部始终使用 480 × 640 的坐标，手机上只是缩小显示。

`context.fillStyle` 设置接下来使用的颜色。
`context.fillRect(x, y, width, height)` 在指定左上角位置绘制一个实心矩形。

篮子宽 100，因此居中的 x 是 `(480 - 100) / 2 = 190`。y 是 `640 - 80 = 560`。

绘制顺序为背景 → 地面 → 篮子 → 篮子装饰。后画的图形会盖在先画的图形上。

## 你的练习

打开 public/game.js，每次只改一处，然后刷新：

1. 把 basket.color 改为 '#5b8def'，观察篮子颜色。
2. 把 basket.x 改为 50，观察篮子向左移动。
3. 把 basket.y 改为 400，观察篮子向上移动。
4. 将 x 和 y 恢复原值，解释为什么减小 y 会向上移动。

## 第二步：键盘与动画循环

`keydown` 把按下的键加入 pressedKeys，`keyup` 将它移除。Set 是不重复的集合，按住键时收到重复事件也不会重复添加。

`requestAnimationFrame(gameLoop)` 请求浏览器在下一帧调用 gameLoop。每一帧先更新篮子的位置，再绘制整个场景，最后预约下一帧。

`deltaTime` 表示距离上一帧经过的秒数。移动距离 = 方向 × 每秒速度 × 经过的秒数。例如速度 300，经过 0.02 秒，就移动 6 像素。这样不同屏幕刷新率下移动速度基本一致。

左方向为 -1，右方向为 1，不按或同时按左右则为 0。篮子的上沿左右各突出 4 像素，所以 x 限制在 4 到 376 之间。窗口失去焦点时清空按键，避免篮子持续移动。

练习：将 basket.speed 从 300 改为 150，刷新后感受速度变化；再改为 450，比较区别。修改浏览器代码只需要刷新页面。

## 第三步：一枚下落金币

`coin.x`、`coin.y` 是圆心，`coin.radius` 是半径。`context.arc(x, y, radius, 0, Math.PI * 2)` 创建完整圆形，`fill()` 填充，`stroke()` 描边。

动画循环调用 `updateCoin(deltaTime)`：每帧下落距离 = `coin.speed × deltaTime`。只有 `coin.y - coin.radius > canvas.height`，即金币的上沿也越过底部，才让圆心回到 `-coin.radius`。新横坐标限制在半径到画布宽度减半径之间，保证金币不被左右边缘裁切。

练习：将 `coin.speed` 从 180 改为 90 或 360，刷新后观察下落速度。接住判定和计分见第四步。

验证逻辑：在项目目录运行 `node --test`，检查金币下落、重生及原有篮子移动。测试执行真实游戏脚本，但不代替浏览器视觉验收。


## 第四步：接住金币与计分

页面显示当前得分，初始为 0，刷新后重新开始。金币底边从上方到达篮子上沿，且金币包围盒与篮子主体在水平方向重叠（边缘相切也算）时，得分加 1，金币立即从顶部随机位置重生。篮子装饰外沿不参与判定。

`previousBottom` 保存更新前的金币底边；将更新前后的位置与篮子上沿比较，可以发现两帧之间跨过上沿的金币，避免穿过漏判。已经落到篮子上沿下面的金币，不会因为横向移动篮子而被误算为接住。

`resetCoin()` 统一处理接住和漏接后的重生。漏接不扣分，没有生命数或结束界面。`scoreDisplay.textContent` 把得分写进页面；立即重生确保同一枚金币只计分一次。

运行 `node --test` 验证下落、漏接、接住、边界和篮子移动；真实浏览器视觉效果仍需部署后确认。


## 第五步：生命、结束与重新开始

当前规则：每局初始 3 条生命，接住加 1 分且不扣生命；漏接扣 1 条生命且不扣分。第三次漏接后，金币和篮子停止更新，页面显示最终得分与“重新开始”按钮。第四步描述的是上一阶段规则。

`gameOver` 决定是否更新位置。动画循环仍保持一条，重新开始不会创建额外循环。重开时分数归零、生命恢复为 3、篮子回到中央、金币回到顶部，同时清空按键和上一帧时间，避免继续移动或突然跳动。

`node --test` 额外验证三次漏接结束、结束后状态冻结、重开恢复及动画继续。


## 第六步：手机触控

画布下方的左右按钮支持触屏和鼠标，按住移动，松开停止，原有方向键和 A、D 保留。两侧同时按住时停止，松开一侧后按剩余方向移动。

Pointer Events 用同一套事件处理鼠标和触摸。`setPointerCapture` 确保手指滑出按钮后，松开仍会收到事件；`pointercancel` 和 `lostpointercapture` 也清理状态。按钮的 `touch-action: none` 避免操作时页面滚动。

指针与键盘状态独立记录，触控释放不影响仍按住的键。失去窗口焦点、游戏结束和重新开始都会清除输入，防止篮子持续移动。测试验证事件处理逻辑，真实手机触摸和视觉效果需部署后实测。


## 完整一局：开始与暂停

打开页面先点击“开始游戏”；运行中可暂停和继续。切换窗口或页面进入后台会自动暂停，回到页面后手动继续，避免离开时损失生命。暂停冻结金币和篮子，继续不会补算暂停时间，也不会保留旧按键。结束后点击“重新开始”即可再玩一局。
