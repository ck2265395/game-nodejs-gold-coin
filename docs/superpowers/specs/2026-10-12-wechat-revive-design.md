# 微信 Native 支付续命

游戏结束后可购买 0.01 元续命，恢复 1 条生命，保留分数和关卡，清空危险的屏幕金币，手动继续。价格固定为人民币 1 分，由服务器决定。电脑使用微信扫描 Native 二维码；不提供模拟成功入口。

Express 提供订单创建、查询、兑换和微信回调；SQLite 持久化订单和浏览器会话。HttpOnly/SameSite cookie 隔离订单，POST 验证 Origin。每个死亡标识最多一个订单，兑换用数据库原子更新保证一次性，重复兑换仅返回同一结果。

微信 API v3：商户 RSA 签名；所有成功响应、查单及回调均用配置的微信支付公钥验证签名和时间。回调 AES-256-GCM 解密，核对商户号、appid、订单号、人民币金额 1 分和成功状态。查单补偿回调延迟。无配置时关闭支付，游戏保持可用。服务重启保留订单。

用户明确要求直接开发、自动提交推送。Native 方式已确认。支付商户配置从服务器安全环境变量与私钥/公钥文件读取，不提交密钥。使用 Node.js 24 与单进程 SQLite；数据库必须保留在服务器持久目录。支付启用要求公开 HTTPS 回调地址。

浏览器保存死亡/兑换后的恢复快照，刷新后恢复暂停状态和当前支付状态；不能把前端“支付成功”作为到账证据。订单创建失败可重试同一订单，支付网络错误不兑换。取消面板不会取消微信中的订单，允许重新打开检查到账。

限制：当前小游戏的分数由浏览器计算，支付接口只保证真实到账及订单一次兑换，不提供竞技反作弊或账号跨设备同步。上线前需商户配置及一次真实 0.01 元支付、回调、重复回调、断网重试联调。
