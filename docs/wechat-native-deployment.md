# 微信 Native 0.01 元续命部署

代码已接入真实微信支付 API v3，当前云环境没有商户配置，支付入口自动隐藏，未进行真实扣款测试。不是模拟支付。需要阿里云服务器上 Node.js 24、已开通 Native 的微信商户、绑定该商户的 AppID、公开 HTTPS 游戏域名。

## 宝塔配置

用 `work` 分支代码，安装 `pnpm install --frozen-lockfile`，单进程执行 `npm start`。沿用 README 的 `/gold-coin/` 反向代理，保留原网站。端口选服务器确认空闲的端口。不要在 URL、聊天或 Git 中传递密钥。

在宝塔 Node 项目的安全环境配置中设置以下变量。文件放在项目目录外，仅运行游戏的系统用户可读。API v3 密钥是本机解密回调使用的真实32字节密钥，不能用网络代理占位值代替。

| 环境变量 | 内容 |
| --- | --- |
| `WX_MCH_ID` | 微信支付商户号 |
| `WX_APP_ID` | 已绑定商户的 AppID |
| `WX_MERCHANT_SERIAL` | 商户 API 证书序列号，用于商户签名标识 |
| `WX_PRIVATE_KEY_PATH` | 商户 RSA API 私钥 PEM 文件绝对路径 |
| `WX_PAY_PUBLIC_KEY_PATH` | 从微信商户平台获取的微信支付公钥 PEM 文件绝对路径 |
| `WX_PAY_PUBLIC_KEY_ID` | 与该公钥匹配的微信支付公钥 ID，通常以 `PUB_KEY_ID_` 开头 |
| `WX_API_V3_KEY_PATH` | 仅包含 API v3 密钥的文本文件绝对路径 |
| `PUBLIC_BASE_URL` | `https://mitongxue.cn/gold-coin` |
| `PAYMENT_DB_PATH` | 持久化 SQLite 数据库绝对路径，例如项目外专用数据目录的 `payments.sqlite` |
| `PORT` | 实际空闲的内部端口 |

本实现使用微信支付公钥模式；商户证书序列号和微信支付公钥 ID 是两个不同配置。微信更新公钥时，按平台公布的新公钥和 ID 一起更新安全文件/配置并重启；签名 ID 不匹配会拒绝响应和回调，不会跳过验签。API 私钥与密钥文件建议权限 600、所属目录700。

HTTPS 回调：`https://mitongxue.cn/gold-coin/api/pay/notify`。Nginx 需要原样转发 JSON 请求正文，不设置基础认证，不拦截微信 POST 请求。外部只需要开放已有的 HTTPS 443；Node 端口不要开放公网。允许服务器访问 `api.mch.weixin.qq.com:443`。支付 cookie 使用 Secure、HttpOnly、SameSite=Lax，真实支付只能通过配置的 HTTPS 域名操作，不能在普通 HTTP localhost 测试。

启动日志只列出缺失配置名称，不输出配置值。配置缺失或错误时关闭支付，原小游戏仍可运行。访问 `/gold-coin/api/pay/config`，确认 `enabled: true`；这仅证明配置已加载，不能证明实际下单和收款成功。

## 玩家流程

游戏结束点击“微信支付0.01元续命”。服务器决定人民币1分价格，创建10分钟有效订单，返回二维码；手机微信扫码。页面定时查单，回调到达也会更新订单。验签并确认金额、商户和订单匹配后可领取1条生命，保留分数与关卡；清空屏幕金币，从暂停状态手动继续。

每次死亡绑定唯一订单，失败重试复用该订单，避免重复下单。未确认订单存在时不能误重开；可关闭未付款订单后重新开始。如果关单同时付款成功，以实际到账结果为准，不丢弃付费权益。已付款无法用“关闭未付款订单”取消或退款。页面“收起”仅关闭界面，不关闭订单。

订单持久保存，重复回调不重复授予新权益，重复兑换返回同一收据。浏览器保存恢复快照；刷新后在同一浏览器/同一cookie下可继续检查订单。不要清除浏览器数据或切换设备处理同一订单。禁用本地存储时能玩，但刷新恢复不可保证。保留数据库及 SQLite WAL 文件，不得随发布目录清空。备份使用 SQLite 在线备份能力，或停本项目服务后备份数据库和相关 WAL 文件。

支付记录用于单机浏览器小游戏；现有分数计算仍在客户端，不用于有奖励的排行榜或竞技反作弊。会话不等于账号，不提供跨设备付费权益同步。上线后通过微信商户平台按本地订单号对账；异常已付款订单保留记录后由商户处理，代码不自动退款。

## 上线验收（尚未执行）

1. 在实际 HTTPS 页面创建一笔0.01元订单，微信二维码可扫描，商户后台可看到正确订单和金额。
2. 实际支付0.01元，确认验签后的回调或查单将订单变为paid，兑换后生命为1，分数/关卡不变。
3. 重复回调/兑换不增加第二次续命；关闭未付款订单后可重开，付款与关单竞态不丢失权益。
4. 支付后断网、刷新及重启本项目，订单仍存在并可恢复。模拟错误金额/签名只能在自动化测试里验证，不修改真实支付金额。
